Architecture & Control Specifications

A.I.R.A. VERIFICATION GATES

Each control evaluates a specific risk boundary and reports an exact state: AVAILABLE, NOT_AVAILABLE, or NOT_SUPPORTED. Controls that cannot be evaluated are reported as limitations rather than fabricated passes.

Gate Control Name Applicability Failure Mode Interrogated Testing Mechanism Failure Action
C1 STATIC AST INTEGRITY AVAILABLE Grammar errors, syntax malformations, and invalid type annotations. Parses source code into complete ASTs prior to test execution. Validates token grammar conformance. Immediate Reject
C2 PROJECT & USER TESTS AVAILABLE Project test failures and custom user test failures. Executes repository test suite and uploaded custom user tests inside hardened Docker container. Immediate Reject
C3 INDEPENDENT INVARIANTS NOT_AVAILABLE Boundary edge conditions and invariant violations. Runs decoupled invariant checks. Reports NOT_AVAILABLE for arbitrary user uploads without independent suites. Policy Block
C4 REGRESSION NOT_AVAILABLE Breaking preexisting callers, modified signatures, or backward incompatibility. Compares test behavior against a baseline commit reference. Reports NOT_AVAILABLE without git history. Policy Block
C5 MUTATION RESILIENCE NOT_SUPPORTED Vacuous tests that pass trivially without genuinely verifying code logic. Synthetically injects AST mutations into code. Reports NOT_SUPPORTED for standalone archive uploads. Policy Review
C6 SECURITY ANALYSIS AVAILABLE CWE-22 path traversal, dangerous subprocess sinks, eval, and hardcoded secrets. AST visitor tracks data flows from untrusted inputs into dangerous filesystem or OS sinks. Security Veto
Security & Isolation Jail

ZERO-NETWORK SANDBOX JAIL

Untrusted AI-generated code never runs on the host filesystem or with network privileges.

Zero Network Access

Containers are spawned with socket creation disabled. Proposed code cannot exfiltrate environment variables, access cloud metadata services, or contact external servers.

Docker flag: --net none

Read-Only Root Filesystem

The host file tree is mounted read-only. File modifications are constrained to an ephemeral memory-backed working directory destroyed upon run completion.

Mount: --read-only /tmp:tmpfs

Strict Resource & PID Caps

CPU quotas (1.0 core), memory ceilings (1024 MB), and process limits (max 100 PIDs) neutralize fork bombs, infinite recursion, and runaway AI loops.

Limits: --memory 1g --pids-limit 100
